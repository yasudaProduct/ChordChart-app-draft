## 技術スタック

### フロントエンド

| Next.js | 14 | React フレームワーク (App Router) |
| React | 18.3 | UI ライブラリ |
| TypeScript | 5.4 | 型安全な JavaScript |
| Tailwind CSS | 3.4 | ユーティリティファースト CSS |
| Zustand | 4.5 | クライアント状態管理 |
| SWR | 2.4 | サーバーデータ取得・キャッシュ |
| Clerk | 6.x | 認証 |

### バックエンド

| 技術        | 用途                    |
| ----------- | ----------------------- |
| Hono        | 軽量 Web フレームワーク |
| Drizzle ORM | 型安全な ORM            |
| Zod         | バリデーション          |
| jose        | JWT 検証（Clerk）       |
| tsup        | ビルドツール            |
| vitest      | テストフレームワーク    |

### インフラ

| サービス           | 用途                       |
| ------------------ | -------------------------- |
| Cloudflare Pages   | フロントエンドホスティング |
| Cloudflare Workers | バックエンドホスティング   |
| Clerk              | 認証・認可                 |
| Neon               | PostgreSQL データベース    |
| GitHub Actions     | CI/CD                      |

## データフロー

### 1. 認証フロー

```
ユーザー → Clerk → JWT トークン取得
         ↓
フロントエンド → Authorization ヘッダーに JWT を付与
         ↓
バックエンド API → JWKS で JWT 検証 → リクエスト処理
```

### 2. データ取得フロー

```
フロントエンド → API リクエスト (fetch)
         ↓
バックエンド API
  └→ Route Handler → Service → Drizzle ORM → PostgreSQL
         ↓
レスポンス (JSON) → フロントエンド → 状態更新 (Zustand) → UI 更新
```

### 3. データ更新フロー

```
ユーザー操作 → Zustand 状態更新 (楽観的更新)
         ↓
API リクエスト → バックエンド処理 → DB 更新
         ↓
成功: 確定 / 失敗: ロールバック
```
