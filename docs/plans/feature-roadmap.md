# 機能拡充ロードマップ（実装ギャップ分析ベース）

## 概要

現状の実装（フロントエンド / バックエンド / DB スキーマ / ドキュメント）を横断調査した結果に基づき、以下を優先度付きの実行ロードマップとして整理する。

1. **不足している機能** — ロードマップ・コンセプト・DB スキーマで意図されているのに、**未実装・機能不全・ハリボテ**になっている「MVP の穴」
2. **サービス拡大のための追加機能・サービス** — 現状スコープの先、成長ドライバとなる新規機能

本書は `docs/project/concept.md` の構想ロードマップ（Phase 1〜3）を置き換えるものではなく、**実装との差分（ギャップ）起点で「どの順に埋めるか」を実行可能な粒度に落とし込んだもの**。役割分担は次の通り。

| ドキュメント                        | 役割                                            |
| ----------------------------------- | ----------------------------------------------- |
| `project/concept.md`                | 何を目指すか（Vision・構想ロードマップ）        |
| `features/overview.md`              | 機能一覧（実装済み / 開発予定の台帳）           |
| **本書 `plans/feature-roadmap.md`** | 今の実装との差分をどの順で埋めるか（Execution） |

> 注: 現時点のデプロイ先はステージング（`develop`）のみで、本番（`main`）は未リリース。したがって「本番リリース前に塞ぐべき穴」を最上位マイルストーン（M0）として扱う。

## 現状サマリ

### 実装済みのコア機能

| 領域             | 実装済みの内容                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| 楽曲 CRUD        | 作成 / 一覧 / 詳細 / 更新（保存）/ 削除（バックエンド API 連携）                                  |
| コード譜エディタ | コード配置（クリック / ドラッグ移動）、セクション操作（追加・複製・並べ替え・種別切替）、歌詞入力 |
| 表示・出力       | ライブプレビュー、詳細表示、印刷（`window.print()`）                                              |
| 検索             | 公開曲検索（title / artist の部分一致・ILIKE）、一覧内クライアントフィルタ                        |
| 認証             | Clerk 経由の Google OAuth、認証モーダル誘導                                                       |
| デモモード       | 登録不要、localStorage 保存                                                                       |
| マイページ       | 可視性別の件数集計、最近編集した曲                                                                |
| 共有（簡易）     | `/share/{song.id}` の URL をクリップボードにコピー                                                |

### 調査で判明した構造的な特徴（設計上の前提）

- **content は正規化ゼロ** — コード譜本体は `Songs.Content`（text 型）に 3 段ネストの JSON 文字列で保存され、DB からは検索・集計不能。
- **スキーマ先行で未接続の機能がある** — `Bookmarks` / `SongShares` テーブルと `specific_users` visibility は定義・seed・index まであるが、API・サービス・UI が皆無。
- **visibility が実質固定** — 作成時 `private` 固定・更新で変更不可（後述）。
- **テストが実質ゼロ** — backend にテストファイル無し、frontend はテスト基盤未導入。
- **再レンダリング最適化ゼロ** — `React.memo` が frontend 全体で 0 箇所（詳細は `plans/frontend-component-guidelines-and-refactoring.md`）。

## 優先度付きロードマップ（マイルストーン）

concept.md の構想 Phase と対応させつつ、**実装ギャップ起点で実行順を組み直したもの**。

### M0: 本番リリース前の必須ライン 🔴

本番公開の前提として塞ぐべきセキュリティ・土台。

- **G17** Webhook 署名検証（セキュリティホール）
- **G1** visibility 変更 UI/API（共有・公開が成立する土台）

### M1: MVP を"謳い通り"にする

コンセプトの 4 本柱（作る / 演奏する / 管理する / 出力する）を実装で満たす。concept.md の **Phase 2 相当**。

- **G5** 移調（transpose）
- **G2** 正式な共有機能（SongShare トークン）
- **G10** PDF エクスポート
- **G9** 自動スクロール / 演奏モード
- **G6** コード補完の実ロジック化（G7 キー自動検出も併せて）

### M2: 成長フェーズ

ライブラリとしての使い勝手・回遊性を高める。

- **G3** ブックマーク
- **G14 / G15** ページネーション ＋ フィルタ / ソート
- **E10** タグ / ジャンル / 難易度
- **E6** セットリスト
- **G13** ダークモード
- **G18 / G19** テスト基盤 ＋ 再レンダリング最適化（品質の底上げ）

### M3: 拡大フェーズ

コミュニティ・プラットフォーム展開。concept.md の **Phase 3 相当**。

- **E1〜E5** コミュニティ機能（フォロー / いいね / コメント / フォーク / モデレーション）
- **G4** 特定ユーザー共有
- **E12 / E13** バージョン履歴 ＋ 共同編集
- **E14 / E15** AI コード検出・提案
- **E16 / E17** PWA / モバイルアプリ
- **E19** マネタイズ
